# Space 应用功能修复指南

本指南用于修复已有 Space 应用的功能、交互与视觉问题。节点定位、下载、覆盖原路径、重新发布和清理统一执行 [`edit-flow.md`](edit-flow.md)；本文件只规定修复判断、优先级和验收标准。

## 1. 适用场景

出现下列任一问题时加载本指南：

- 按钮、表单、筛选、分页、弹层、菜单或其他控件不可用；
- 操作后界面没有及时反馈，状态切换不清楚或用户无法继续；
- 键盘、触控、滚动、焦点或窄屏操作体验异常；
- 信息层级、排版、间距、颜色、组件样式或响应式布局明显退化；
- 页面数据已经正确返回，但绑定、渲染或展示结果不符合应用意图。

修复不等于重新设计业务。默认保留原应用内容、数据关系和正常功能，只处理实际问题与必要的体验优化。

## 2. SDK 与返回数据无条件可信

`window.__SPACE_PAGE__.database` SDK、合同中定义的方法和 SDK 成功返回的数据均是权威结果，可以无条件信任。修复过程中不得因为怀疑 SDK 或返回数据而增加：

- 二次查询、重复拉取或额外的数据正确性核验；
- 数据形状猜测、字段纠错、兼容旧字段或私自重命名；
- mock 数据、fallback 数据、静态替代数据或静默默认值；
- 为修正所谓异常返回而编写的归一化、过滤或防御性分支。

SDK 成功返回后直接按 [`database/database-sdk-contract.md`](database/database-sdk-contract.md) 和 [`database/database-sdk-schema.md`](database/database-sdk-schema.md) 的字段消费。页面表现异常时，优先检查页面侧的事件绑定、参数使用、状态同步、DOM 渲染、组件逻辑、CSS 和响应式规则，不把问题归因于 SDK 数据。

本信任原则不允许改变 SDK 方法名、snake_case 参数、真实字段名或真实 `database_id`。只有页面实际调用方式违反 SDK 合同时，才修改相关调用代码，并保持改动最小。

## 3. 修复优先级

严格按以下顺序工作：

1. **核心交互可用：** 先恢复用户完成主要任务的操作链路；
2. **交互体验清晰：** 再优化反馈、状态、键盘、触控、焦点、弹层、滚动和响应式交互；
3. **视觉样式完善：** 然后优化信息层级、排版、间距、颜色、边框、圆角、阴影和组件一致性；
4. **最小代码调整：** 只修改支持上述目标所必需的页面代码，不开展无关的数据层重构。

不得以重写 SDK 数据处理、替换真实数据或大规模业务重构代替交互与样式修复。已有健康功能应原样保留。

## 4. 建立修复基线

下载原 HTML 并运行页面分析后，记录：

- 原 `node ID`、`spaceId`、当前路径、文件名和 `parent_id`；
- 原 Database ID 集和页面模式；
- 主要任务路径、入口控件、操作结果和页面状态；
- 桌面、平板、移动窄屏的关键布局；
- 已正常工作的内容、交互和视觉区域。

只在临时副本中修复。除非用户明确要求迁移或换数据，否则必须保留原 node ID、Space ID、当前路径、父目录和 Database ID。

## 5. 交互修复清单

先逐条实际操作主要任务路径，再处理样式：

- 按钮、链接、筛选、排序、分页、标签页和菜单可触发正确动作；
- 表单标签清楚，输入、校验、提交、取消和重复提交行为连贯；
- 写操作期间使用 submitting/disabled 状态，并提供明确的完成反馈；
- loading、empty、ready 等状态切换及时，不遮挡已有可用内容；
- 键盘可到达并操作主要控件，焦点顺序合理，`:focus-visible` 清晰；
- 触控目标尺寸和间距足够，不依赖 hover 才能访问关键功能；
- 弹层、菜单和浮层层级正确，打开后焦点明确，关闭和返回路径可用；
- 页面与局部容器滚动符合预期，不锁死正文或制造无意横向滚动；
- 桌面、平板、移动窄屏上的主要操作都能完成。

如果 SDK 数据已成功返回但页面未正确显示，直接修复页面的数据绑定、渲染时机和状态更新逻辑，不新增数据兜底。

## 6. 样式优化清单

核心交互可用后再优化视觉：

- 主要信息与主要操作具有明确层级，首屏重点清晰；
- 字号、字重、行高、段落宽度和留白保持可读；
- 使用有限且一致的颜色、间距、圆角、边框和阴影 token；
- 同类按钮、输入框、卡片、表格和状态提示样式一致；
- hover、active、focus-visible、disabled、submitting 状态有可辨识反馈；
- 表格、图表、卡片和操作区在窄屏合理换行、折叠或横向滚动；
- 对比度足够，关键信息不只依赖颜色表达；
- 动效简短并服从 `prefers-reduced-motion`；
- 不为了视觉效果删除业务内容、改变语义或破坏已经正常的交互。

具体视觉方法按 [`beautify-flow.md`](beautify-flow.md) 和 [`beautify/beautify-guide.md`](beautify/beautify-guide.md) 执行；修复场景始终以可用性和一致性优先。

## 7. 完成与发布

修复完成必须满足：

1. 主要任务路径已逐项实际操作并可完成；
2. 键盘、触控、焦点、提交状态、弹层和滚动行为符合交互意图；
3. 桌面、平板和移动窄屏样式已检查；
4. SDK 成功返回数据被直接消费，没有新增 mock、fallback、纠错或重复查询；
5. 原 node ID、Space ID、路径、父目录和未要求变更的 Database ID 保持不变；
6. 动态页通过 SDK lint，所有页面通过 resource lint 和 2 MiB 检查；
7. 按 [`edit-flow.md`](edit-flow.md) 覆盖原路径、沿用原 node ID 发布并返回本次 publish URL；
8. 本轮本地临时产物按安全规则清理。
