# RPC 与 Dubbo

## 基础

RPC（Remote Procedure Call）远程过程调用，通过网络编程帮助调用远程计算机上某个服务的方法，无需了解底层网络细节。就像调用本地方法一样简单。

## 核心

### RPC 原理

**核心组件**：
1. **客户端（消费端）**：调用远程方法的一端
2. **客户端 Stub**：代理类，负责将调用方法、类、参数组装成消息（RpcRequest）并发送
3. **网络传输**：Socket 或 Netty（推荐）
4. **服务端 Stub**：接收到请求后执行对应方法并返回结果（RpcResponse）
5. **服务端（提供端）**：提供远程方法的一端

**流程**：
- 本地调用远程方法 → 客户端 Stub 封装消息 → 发送到服务端 → 服务端执行方法 → 返回结果给客户端

### TCP 粘包问题

TCP 基于字节流传输，无消息边界，存在粘包问题。需要自定义协议（消息头+消息体）来区分消息边界。

### HTTP vs RPC

**HTTP**：超文本传输协议，B/S 架构下统一标准，默认 80 端口，通过 DNS 解析服务发现

**RPC**：远程过程调用，是一种调用方式，C/S 架构下自定义协议，可使用 TCP/UDP/HTTP，采用专用服务发现（Consul/Etcd/Nacos/ZooKeeper）

**区别**：
- HTTP 需要考虑浏览器行为，RPC 定制化程度高
- RPC 可用 Protobuf 等高效序列化协议，性能更好
- RPC 建立连接池复用连接，HTTP 1.1 靠 keep alive 复用

### Dubbo 架构

Apache Dubbo 是高性能、轻量级开源 RPC 框架，解决微服务架构下的服务治理与通信问题。

**六大核心能力**：
1. 面向接口代理的高性能 RPC 调用
2. 智能容错和负载均衡
3. 服务自动注册和发现
4. 高度可扩展能力
5. 运行期流量调度
6. 可视化服务治理与运维

**核心角色**：
- **Container**：服务运行容器（必须）
- **Provider**：服务提供方，向注册中心注册（必须）
- **Consumer**：服务消费方，订阅服务（必须）
- **Registry**：注册中心（非必须）
- **Monitor**：监控中心（非必须）

**Invoker**：Dubbo 对远程调用的抽象，分为服务提供 Invoker 和服务消费 Invoker，通过动态代理屏蔽远程调用细节。
