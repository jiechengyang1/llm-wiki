# 资料摘要：垃圾回收器

## 经典垃圾回收器

| 回收器 | 作用区域 | 算法 | 特点 |
|--------|----------|------|------|
| Serial | 新生代 | 复制 | 单线程、Client模式 |
| ParNew | 新生代 | 复制 | 并行、Server模式 |
| Parallel Scavenge | 新生代 | 复制 | 吞吐量优先 |
| Serial Old | 老年代 | 标记-整理 | 单线程 |
| Parallel Old | 老年代 | 标记-整理 | 并行、吞吐量优先 |
| CMS | 老年代 | 标记-清除 | 低延迟、并发 |
| G1 | 新生代+老年代 | 复制+标记-整理 | 区域化、可预测停顿 |

## 性能指标

- **吞吐量** = 用户代码时间 / 总时间
- **暂停时间** = STW时长
- 二者矛盾，不可兼得

## CMS回收器

**四阶段：**
1. 初始标记（STW）- 标记GCRoots直接引用
2. 并发标记 - 遍历对象图
3. 重新标记（STW）- 修正并发期间变化
4. 并发清除 - 清理死亡对象

**优点：** 低延迟
**缺点：** 内存碎片、CPU敏感、浮动垃圾

## G1回收器

**特点：**
- Region分区（1MB-32MB）
- 优先回收价值最大Region
- 可预测停顿时间模型
- JDK9默认

**回收过程：**
1. Young GC
2. Concurrent Marking
3. Mixed GC

## ZGC

- 低延迟（<10ms）
- 可扩展至TB级堆
- JDK11引入

## 选择建议

- 单CPU：Serial
- 吞吐量优先：Parallel
- 低延迟：CMS/G1
- 大内存：G1/ZGC
