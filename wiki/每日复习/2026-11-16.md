# 每日知识点 · 2026-11-16（第 1/66 天）

## 今日新知：[[JAVA基础-上]]

### 要点速览

- **JVM 是核心**：一次编译，到处运行；JDK = JRE + 开发工具（javac 等），JRE = JVM + 类库
- **执行链路**：.java → 编译成 .class 字节码 → JVM 解释执行；热点代码触发 **JIT** 编译缓存机器码 → Java 是「编译 + 解释共存」的语言
- **基本类型 vs 包装类型**：基本类型在栈、包装类型在堆；**Integer 缓存 [-128, 127]**；泛型只能用包装类型
- **== vs equals**：== 基本类型比值、引用类型比地址；equals 未重写时等价 ==，String 等重写后比较内容
- **hashCode**：与 equals 配合供 HashMap/HashSet 高效定位 → **重写 equals 必须重写 hashCode**
- **面向对象三大特性**：封装（私有 + get/set）、继承（私有不可访问）、多态（重载=编译期，重写=运行期）
- **String 不可变**：final 类 + final 数组（JDK9 起存 byte[]）；StringBuffer 线程安全 / StringBuilder 非线程安全
- **深浅拷贝**：浅拷贝只复制引用地址；深拷贝完全复制（Cloneable / 序列化 / 手动递归）
- **语法糖**：泛型、自动拆装箱、变长参数、Lambda 等，JVM 不识别——编译阶段解糖

### 自测三题（先自己答，再展开对答案）

1. 为什么说 Java 是「编译与解释共存」的语言？JIT 在其中扮演什么角色？
2. `Integer a = 127, b = 127` 与 `Integer c = 128, d = 128`，两组 `==` 的结果分别是什么？为什么？
3. 重写 `equals()` 为什么必须同时重写 `hashCode()`？

> [!success]- 参考答案
> 1. Java 源码先编译为字节码（编译），JVM 内解释器逐行解释执行（解释），热点代码由 JIT 编译为机器码缓存复用——所以两者共存。
> 2. 127 为 `true`，128 为 `false`：Integer 缓存范围 [-128, 127]，127 的包装对象来自缓存同一实例；128 超出缓存，各自 new 出新对象，== 比较的是地址。
> 3. 容器（HashMap/HashSet）先按 hashCode 定位桶再按 equals 精确比较。只重写 equals 不重写 hashCode，两个"相等"的对象哈希不同，可能落进不同桶，HashMap 中就会同时存在"相等"的两个 key。
