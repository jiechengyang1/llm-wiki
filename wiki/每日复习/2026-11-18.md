# 每日知识点 · 2026-11-18（第 3/76 天）

## 今日新知：[[并发编程]]

### 要点速览

- **进程 vs 线程**：进程 = 拥有独立内存空间的应用程序实体；线程 = 进程内的多条执行路径，**共享进程内存**
- **并发 vs 并行**：并发 = 同一实体**交替**执行多个任务；并行 = **真正同时**执行
- **管程 Monitor**：保证互斥访问的同步机制，**每个 Java 对象都有一个 Monitor**（synchronized 的底层依据）
- **线程创建三种方式**：继承 Thread / 实现 Runnable / 实现 Callable + FutureTask（唯一能拿到返回值的方式）
- **用户线程 vs 守护线程**：用户线程完成业务；守护线程服务他人（如 GC），程序结束 JVM 终止
- **线程生命周期**：NEW → RUNNABLE →（BLOCKED / WAITING）→ TERMINATED
- **JUC 全家桶五大件**：原子类（CAS）· 锁（ReentrantLock / ReadWriteLock）· 同步器（AQS / CountDownLatch / CyclicBarrier）· 并发集合（ConcurrentHashMap / CopyOnWriteArrayList）· 线程池（ThreadPoolExecutor / Executors）

### 自测三题（先自己答，再展开对答案）

1. 进程和线程的本质区别是什么？线程共享了进程的什么资源？
2. 并发和并行的区别是什么？各举一个例子。
3. 用户线程和守护线程有什么区别？JVM 在什么时机退出？

> [!success]- 参考答案
> 1. 进程拥有独立的内存空间，是资源分配的单位；线程是进程内的执行路径，共享进程的内存（堆、方法区等），只拥有自己的栈和程序计数器。
> 2. 并发是同一实体交替执行多个任务（如单核 CPU 时间片轮转），并行是真正同时执行（多核 CPU 各跑一个任务）。
> 3. 用户线程完成业务逻辑，守护线程服务其他线程（典型如 GC）。JVM 等所有用户线程结束后才终止——守护线程不会阻止 JVM 退出。

## 昨日回顾：[[JVM和Java体系]]

- JVM 是**跨语言的平台**：只认字节码，Groovy、Scala、Kotlin、JRuby 编译成 Class 文件都能跑
- JVM 采用**基于栈**的指令集架构：可移植性好、实现简单，代价是性能略低、指令更多
- 执行一个 Java 程序 = 执行一个 JVM 进程，程序结束 JVM 随之退出
