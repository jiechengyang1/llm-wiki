# 每日知识点 · 2026-11-28（第 6/76 天）

## 今日新知：[[数据库基础知识]]

### 要点速览

- **四个基本概念**：DB（数据集合）· DBMS（操纵管理软件）· DBS（软件+数据库+DBA）· DBA（管理员）
- **关系术语**：元组=一行；码=能唯一标识实体；候选码=最小唯一属性组；主码=选定的那个候选码；外码=别的表的主码
- **ER 图三要素**：实体（矩形）、属性（椭圆）、联系（菱形，含数量对照关系）
- **1NF**：属性不可再分——关系型数据库的最基本要求
- **2NF**：消除非主属性对主键的**部分函数依赖**——非主键字段必须**完全依赖**主键
- **3NF**：消除**传递函数依赖**——非主键字段之间不能相互依赖，必须相互独立
- **drop vs delete vs truncate**：DELETE（DML，删指定行，**可回滚**）；TRUNCATE（DDL，清空全表且**重置自增 ID**，不可回滚）；DROP（DDL，删除整张表含结构，不可回滚）
- **NoSQL = Not Only SQL**：键值/文档/图形模型；**横向扩展**（加节点）vs SQL 的纵向扩展；schema 灵活；**最终一致性** vs SQL 的强 ACID
- **NoSQL 优势与代表**：灵活架构、可扩展、针对特定模型高性能——Redis、MongoDB、HBase、Cassandra

### 自测三题（先自己答，再展开对答案）

1. 三大范式分别消除了什么问题？每个用一句话说清。
2. DELETE、TRUNCATE、DROP 三者从 SQL 类型、回滚能力、作用范围上有什么区别？
3. SQL 和 NoSQL 在扩展方式与事务模型上的核心差异是什么？

> [!success]- 参考答案
> 1. 1NF：属性不可再分（原子性）；2NF：消除非主属性对主键的部分函数依赖，非主键字段完全依赖主键；3NF：消除传递函数依赖，非主键字段之间相互独立。
> 2. DELETE 是 DML，删除指定行数据，事务内可回滚；TRUNCATE 是 DDL，清空全表数据并将自增 ID 重置，不可回滚；DROP 是 DDL，删除整张表（结构和数据一起删），不可回滚。
> 3. SQL 纵向扩展（提升单机配置）、强 ACID 事务、固定 schema；NoSQL 横向扩展（加服务器节点）、灵活 schema、最终一致性（BASE），针对特定数据模型优化性能。

## 昨日回顾：[[分布式锁]]

- **Redis 加锁必须原子**：`SETNX` 和 `EXPIRE` 分开执行，中间崩溃 → 锁永不过期 → 死锁；用 Lua 脚本或 `SET key value NX EX` 单命令解决
- **Redisson 三大能力**：看门狗自动续期（默认锁 30s、每 10s 续一次）· 可重入（hash 存重入次数）· 公平锁（有序队列）
- **三大经典问题**：锁过期业务未完成 → 看门狗；主从切换丢锁 → RedLock 多数派；误删他人锁 → value 存唯一标识 + Lua 校验后删除
