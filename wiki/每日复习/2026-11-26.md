# 每日知识点 · 2026-11-26（第 4/76 天）

## 今日新知：[[Java集合]]

### 要点速览

- **两大顶层体系**：Collection（List / Set / Queue 三支）+ Map（键值对，独立一支）
- **List 四实现**：ArrayList（数组，随机访问/尾插）、LinkedList（双向链表，频繁插删）、Vector（同步数组，已废弃）、CopyOnWriteArrayList（读多写少的并发场景）
- **Set 三件套**：HashSet（底层 HashMap，无序）、LinkedHashSet（保持插入顺序）、TreeSet（底层红黑树，自然排序）
- **Map 六将**：HashMap（数组+链表+红黑树，高性能）、LinkedHashMap（+双向链表保插入序）、TreeMap（红黑树排序）、Hashtable（已废弃）、ConcurrentHashMap（**高并发首选**）、ConcurrentSkipListMap（跳表，有序高并发）
- **fail-fast 机制**：迭代时校验 modCount 是否被改动，变了就抛 `ConcurrentModificationException`
- **线程安全三套方案**：`synchronizedXxx` 包装类（全局锁，性能差）→ concurrent 包（ConcurrentHashMap 分段锁/CAS）→ BlockingQueue（生产者-消费者模式）
- **单线程选型**：随机访问 ArrayList / 频繁插删 LinkedList / 键值对 HashMap / 需要排序 TreeMap / 需要保序 LinkedHashMap
- **多线程选型**：Map 用 ConcurrentHashMap、List 用 CopyOnWriteArrayList、Set 用 CopyOnWriteArraySet 或 `ConcurrentHashMap.newKeySet()`、生产消费用 BlockingQueue

### 自测三题（先自己答，再展开对答案）

1. ArrayList 和 LinkedList 底层结构分别是什么？各自适合什么场景？
2. HashSet、LinkedHashSet、TreeSet 三者的顺序特性有什么区别？
3. 什么是 fail-fast？它的实现原理是什么？

> [!success]- 参考答案
> 1. ArrayList 底层是数组，支持 O(1) 随机访问、适合尾插；LinkedList 底层是双向链表，插入删除只需改指针、适合频繁插删场景。
> 2. HashSet 无序（底层 HashMap）；LinkedHashSet 保持插入顺序（底层 LinkedHashMap 维护双向链表）；TreeSet 按自然顺序（或 Comparator）排序，底层红黑树。
> 3. fail-fast 指集合在迭代过程中被结构性修改就快速失败。原理：集合用 modCount 记录修改次数，迭代器创建时记录 expectedModCount，每次 next() 检查两者是否一致，不一致立刻抛 ConcurrentModificationException。避免方式：用迭代器自身的 remove()，或改用并发集合（如 CopyOnWriteArrayList）。

## 昨日回顾：[[并发编程]]

- **进程 vs 线程**：进程 = 独立内存空间的应用实体；线程 = 进程内执行路径，**共享进程内存**（只拥有自己的栈和程序计数器）
- **并发 vs 并行**：并发 = 同一实体**交替**执行；并行 = 多核**真正同时**执行
- **用户线程 vs 守护线程**：守护线程服务他人（如 GC），JVM 等所有**用户线程**结束才退出，守护线程不阻止 JVM 退出
