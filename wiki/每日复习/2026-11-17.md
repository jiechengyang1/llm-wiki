# 每日知识点 · 2026-11-17（第 2/66 天）

## 今日新知：[[JVM和Java体系]]

### 要点速览

- **JVM 是跨语言的平台**：Groovy、Scala、Kotlin、JRuby 都能编译成字节码在 JVM 上运行；JVM 只认字节码，不关心源语言
- **语言无关性**：JVM 与 Java 语言没有必然联系，只与 Class 文件格式绑定
- **虚拟机分类**：系统虚拟机（VMware/Visual Box，仿真整个操作系统）vs 程序虚拟机（**JVM**，专门执行单个程序）
- **JVM 三大特性**：一次编译到处运行、自动内存管理、自动垃圾回收
- **整体结构**：类加载子系统 → 运行时数据区（方法区/堆/栈/本地方法栈/PC 寄存器）→ 执行引擎
- **指令集架构**：JVM 采用**基于栈**（零地址指令为主）而非基于寄存器
- **为什么选基于栈**：可移植性好、实现简单——代价是性能略低、需要更多指令
- **生命周期**：启动（引导类加载器创建初始类）→ 执行（Java 程序即 JVM 进程）→ 退出（正常结束 / 异常 / Runtime.exit() / JNI 卸载）

### 自测三题（先自己答，再展开对答案）

1. 为什么说 JVM 是「跨语言的平台」而不仅仅是 Java 的运行环境？
2. JVM 的指令集架构是基于栈还是基于寄存器？这个选择的得与失是什么？
3. JVM 的生命周期中，「执行一个 Java 程序」和「执行 JVM 进程」是什么关系？

> [!success]- 参考答案
> 1. JVM 只关心字节码（Class 文件格式），与 Java 语言本身无必然联系。Groovy、Scala、Kotlin、JRuby 等语言的编译器都能产出 JVM 字节码，所以任何语言只要能编译成合规字节码就能跑在 JVM 上——JVM 是语言无关的平台。
> 2. 基于栈（零地址指令为主）。得：可移植性极佳（不依赖具体硬件寄存器）、实现简单；失：性能低于基于寄存器的架构，完成同样操作需要更多指令。
> 3. 二者等价：执行一个 Java 程序就是执行一个 JVM 进程，程序运行期间 JVM 一直存活，程序结束 JVM 随之退出。

## 昨日回顾：[[JAVA基础-上]]

- JDK = JRE + 开发工具；JRE = JVM + 类库；Java 是「编译 + 解释共存」，热点代码靠 JIT 缓存机器码
- Integer 缓存 [-128, 127]，超出范围的包装类型 == 比较会 false（比地址）；重写 equals 必须重写 hashCode
- String 不可变（final 类 + final 数组）；StringBuffer 线程安全 / StringBuilder 非线程安全
