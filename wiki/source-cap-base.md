# CAP 与 BASE 理论

## 基础

CAP 理论是分布式系统设计的基石，BASE 理论则是 CAP 中 AP 方案的延伸和补充。

## 核心

### CAP 理论

CAP 是 Consistency（一致性）、Availability（可用性）、Partition Tolerance（分区容错性）三个单词首字母组合。

CAP 定理指出：分布式系统设计时，读写操作只能同时满足以下三点中的两个：

- **一致性（C）**：所有节点访问同一份最新数据副本
- **可用性（A）**：非故障节点在合理时间内返回合理响应
- **分区容错性（P）**：网络分区时仍能对外提供服务

**网络分区**：多个节点间网络连通，部分节点网络故障导致分成几块区域。

### CAP 选择

当发生网络分区时，如果要继续服务，强一致性和可用性只能二选一。**P 是前提**，分区容错性是必须实现的。

**分布式系统理论上只能选择 CP 或 AP 架构**，不可能选择 CA 架构。

- CP 架构：ZooKeeper、HBase
- AP 架构：Cassandra、Eureka
- 同时支持：Nacos

**为什么不能选 CA**：分区时，写操作需禁止其他节点读写以保证一致性，这与可用性冲突。

**正常情况下**（无分区），C 和 A 可以同时保证。

### BASE 理论

BASE 是 Basically Available（基本可用）、Soft-state（软状态）、Eventually Consistent（最终一致性）三个短语缩写。**BASE 是对 CAP 中一致性 C 和可用性 A 权衡的结果**。

### BASE 三要素

**基本可用**：允许损失部分可用性。
- 响应时间损失：正常 0.5s，故障时 3s
- 系统功能损失：部分非核心功能不可用

**软状态**：允许数据存在中间状态，不影响系统整体可用性。

**最终一致性**：系统所有数据副本经过一段时间同步后，最终达到一致状态。

### 一致性级别

1. **强一致性**：写入什么就读出什么
2. **弱一致性**：不一定读到最新值
3. **最终一致性**：弱一致性升级，保证一定时间内达到一致

**实现方式**：
- 读时修复：读取时检测不一致并修复（Cassandra Read Repair）
- 写时修复：写入时检测不一致并修复（推荐，对性能消耗低）
- 异步修复：定时对账检测并修复

**分布式一致性的关系**：ACID（事务完整性）→ CAP（分布式理论）→ BASE（AP 方案延伸）
