# 分布式幂等性

## 什么是幂等性

**一次和多次请求某一个资源对于资源本身应该具有同样的结果**

### RESTful API幂等性

| 方法 | 是否幂等 | 说明 |
|------|---------|------|
| GET | 是 | 只读，不改变资源 |
| POST | 否 | 每次执行新增数据 |
| PUT | 视情况 | 直接值更新幂等，累加操作非幂等 |
| DELETE | 视情况 | 唯一值删除幂等，条件删除非幂等 |

### 引入幂等性的代价

- 并行改串行，降低执行效率
- 增加额外控制逻辑，复杂化业务

## 幂等性实现方案

### 1. 数据库唯一主键

- 适用：插入、删除操作
- 限制：需要生成全局唯一主键ID
- 流程：生成分布式ID → 作为主键插入 → 主键重复则表示重复调用

### 2. 数据库乐观锁（版本号）

- 适用：更新操作
- 添加version字段，更新时作为条件
- 类似CAS操作

```sql
UPDATE table SET value=new_value, version=version+1 
WHERE id=1 AND version=old_version
```

### 3. 防重Token令牌

- 适用：插入、更新、删除操作
- 限制：需要全局唯一Token + Redis
- 流程：
  1. 客户端先获取Token
  2. 携带Token发起请求
  3. 服务端验证Token（Redis查找+删除，需保证原子性）
  4. 验证通过执行业务，否则拒绝

> Redis查找与删除需保证原子性（分布式锁或Lua脚本）

### 4. 下游传递唯一序列号

- 适用：插入、更新、删除操作
- 限制：要求第三方传递唯一序列号 + Redis
- 流程：
  1. 下游传递唯一序列号
  2. 服务端以序列号为key存入Redis（**必须设置过期时间**）
  3. 处理前先查Redis判断是否已处理

> 序列号存入Redis**必须设置过期时间**，否则数据无限堆积
