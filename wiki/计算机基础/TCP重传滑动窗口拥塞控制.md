# TCP 重传、滑动窗口、流量控制、拥塞控制

## 基础

TCP 通过重传机制、滑动窗口、流量控制、拥塞控制保证可靠性。

## 核心

### 重传机制

**超时重传**：设定定时器，超过指定时间未收到 ACK 则重发数据。RTO 应略大于报文往返 RTT。

**快速重传**：不以时间为驱动，而以数据驱动，收到连续三个相同 ACK 则快速重传。

**SACK（选择性确认）**：TCP 头部选项字段发送已收数据信息，发送方只重传丢失数据。

**D-SACK（Duplicate SACK）**：告诉发送方哪些数据被重复接收，用于处理 ACK 丢包或网络延时情况。

### 滑动窗口

窗口大小指无需等待确认应答而可继续发送数据的最大值。

发送方滑动窗口：收到 ACK 后窗口右移，缓存已发送数据

接收方滑动窗口：维护已接收数据和控制信息

**累计确认**：通过下一个确认应答进行确认，如收到 ACK 700 则 700 之前数据都已收到

### 流量控制

根据接收方实际接收能力控制发送数据量，防止发送方发送数据超出接收方处理能力。

**发送窗口 = min(拥塞窗口cwnd, 接收窗口rwnd)**

**窗口关闭**：窗口大小为 0 时阻止发送方发数据，需窗口更新通知恢复。

**持续计时器**：防止窗口更新通知丢失导致死锁，计时器超时发送窗口探测报文。

**糊涂窗口综合症**：接收方太忙导致窗口越来越小。解决策略：
- 接收方：窗口小于 min(MSS, 缓存/2) 时通告窗口为 0
- 发送方：Nagle 算法缓存数据，满足条件才发送

### 拥塞控制

避免发送方数据填满整个网络。拥塞窗口 cwnd 动态变化。

**四个算法**：

**慢启动**：每收到一个 ACK，cwnd + 1。cwnd >= ssthresh 时进入拥塞避免。

**拥塞避免**：每收到一个 ACK，cwnd 增加 1/cwnd（即增加 1）。

**快重传**（触发条件不同处理不同）：
- 超时重传：ssthresh = cwnd/2，cwnd = 1
- 快速重传（收到 3 个重复 ACK）：cwnd = cwnd/2，ssthresh = cwnd，进入快速恢复

**快速恢复**：收到 3 个重复 ACK 时不认为网络完全拥塞，执行快重传后进入此阶段。
