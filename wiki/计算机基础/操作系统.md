# 操作系统

## 基础

操作系统是管理计算机硬件与软件资源的程序，作为用户与硬件之间的接口。

## 核心

### CPU 执行过程

1. **程序计数器**读取指令内存地址，控制单元操作地址总线访问内存
2. 指令数据存入**指令寄存器**，程序计数器自增（32位CPU自增4）
3. **指令寄存器**分析指令类型和参数，交由逻辑运算单元或控制单元执行

### 指令流水线

指令分为4级流水线：**Fetch（取指令）→ Decode（指令译码）→ Execution（执行指令）→ Store（数据回写）**

### 缓存结构

CPU Cache 数据加载路径：内存 → L3 Cache（共享）→ L2 Cache（独有）→ L1 Cache（独有，数据/指令分开）→ CPU

越靠近核心访问速度越快。

### CPU Cache 数据结构

Cache Line = 组标记 + 数据块 + 有效位。访问地址 = Index（索引） + Offset（偏移量） + Tag（组标记）

### 缓存写入策略

- **写直达（Write Through）**：同时写入内存和Cache
- **写回（Write Back）**：只写入Cache，替换时才写回内存，标记脏位

### 缓存一致性

**MESI 协议**：
- **Modified（已修改）**：数据已更新但未写回内存
- **Exclusive（独占）**：数据只在一个核心Cache中，与内存一致
- **Shared（共享）**：数据在多个核心Cache中，与内存一致
- **Invalidated（已失效）**：数据已失效

### 伪共享

多个线程共享同一Cache Line的不同变量导致缓存失效。使用 `__cacheline_aligned_in_smp` 宏解决。

### 进程与线程

**进程**是资源分配单位，**线程**是CPU调度单位。Linux 中都用 task_struct 表示，线程共享进程资源（内存空间、文件描述符等）。

### 调度类

- **Deadline**：按deadline调度，实时任务
- **Realtime（FIFO/RR）**：实时任务，优先级0-99
- **Fair（CFS）**：普通任务，优先级100-139，通过vruntime实现公平调度

**优先级**：Deadline > Realtime > Fair

### 进程状态

运行状态、就绪状态、阻塞状态、创建状态、结束状态、阻塞挂起状态、就绪挂起状态。

### 进程通信方式

管道、消息队列、共享内存、信号量、信号、Socket

### 内存管理

**虚拟内存作用**：支持超过物理内存的程序、实现进程地址空间隔离、提供访问保护。

**内存分配流程**：malloc申请虚拟内存 → 访问触发缺页中断 → 有空闲内存则分配，无则回收（后台kswapd或直接回收）→ 仍不足触发OOM Killer

**kswapd回收阈值**：pages_high > pages_low > pages_min

### 内存分配方式

- **brk()**：小于128KB，堆顶指针移动，释放不归还OS
- **mmap()**：大于128KB，文件映射区，释放归还OS

### 文件页回收

- **文件页**：干净页直接释放，脏页先写回磁盘
- **匿名页**：通过Swap机制换出到磁盘

### 零拷贝

**传统方式**：read + write = 4次上下文切换 + 4次数据拷贝

**优化方式**：
- **mmap + write**：减少一次拷贝，3次拷贝
- **sendfile**：2次上下文切换 + 3次拷贝
- **sendfile + SG-DMA**：真正的零拷贝，2次DMA拷贝

### I/O多路复用

**select/poll**：线性遍历，O(n)复杂度，2次拷贝

**epoll**：
- 红黑树管理待检测Socket
- 就绪链表记录就绪事件
- 时间复杂度O(1)

**触发模式**：
- **水平触发（LT）**：满足条件持续通知
- **边缘触发（ET）**：只通知一次，需一次性读完

边缘触发需配合非阻塞I/O。
