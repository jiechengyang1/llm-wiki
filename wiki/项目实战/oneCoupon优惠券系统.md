# oneCoupon优惠券系统

## 秒杀下单支付场景

核心逻辑：**下订单减库存**，难点在于保障秒杀顺利进行 + 延迟付款处理

### 秒杀需要解决的问题
1. 热点数据提前预热
2. 高并发量处理
3. 防止超卖保证数据一致性
4. 保证系统高可用

## 热点数据处理

| 类型 | 说明 | 处理方式 |
|------|------|---------|
| 静态热点 | 可提前预测（秒杀商品） | 提前放入缓存 |
| 动态热点 | 运行时产生 | 动态检测系统运行状态 |

> 超大并发场景下，热点数据可能直接击穿Redis集群

## 高可用保障

### 集群化
避免单点风险，搭建集群（如Redis主从复制→哨兵模式→集群模式）

### 限流
- Redis Lua脚本限流（可针对单个用户）
- Sentinel / Hystrix / Resilience4J
- 辅助手段：答题/验证码、前端按钮防重复点击

### 流量削峰
- **消息队列**进行流量削峰
- 用户秒杀请求先存MQ，再慢慢消费
- MQ还能实现异步解耦（如下单和付款分离）

## 一致性：防止超卖

### 减库存方案

| 方案 | 优点 | 缺点 |
|------|------|------|
| **下单减库存** | 保证不超卖 | 恶意下单不付款占库存 |
| 付款减库存 | 不占库存 | 可能下单成功但付款失败 |

> 一般采用**下单减库存**，超时未付款则释放库存

### Lua脚本原子减库存

```lua
local stockNum = tonumber(redis.call("get", key))
if stockNum < 1 then
    return 0
else
    redis.call('DECRBY', key, 1)
    return 1
end
```

### MySQL与Redis数据一致性

Redis扣减库存成功 → 异步（MQ）同步到MySQL，保证最终一致性

## 订单超时自动取消

将付款任务丢入**延迟队列**：
- 用户规定时间内付款 → 修改订单状态为已付款
- 延迟时间到达 → 删除订单 + 恢复库存

### 延时任务方案

| 类型 | 方案 |
|------|------|
| 单机 | Timer、ScheduledExecutorService、DelayQueue、Spring Task、**时间轮** |
| 分布式 | **Redis**、**MQ** |
