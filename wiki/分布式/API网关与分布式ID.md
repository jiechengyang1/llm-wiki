# API 网关与分布式 ID

## 基础

微服务架构中，网关解决安全认证、流量控制、日志监控等通用功能重复实现的问题，提供请求转发和请求过滤两大核心能力。

## 核心

### API 网关

**核心功能**：
- 请求转发、负载均衡
- 安全认证（身份验证、RBAC 授权）
- 流量控制、熔断降级
- 日志记录、监控告警
- 参数校验、协议转换
- 灰度发布、异常处理
- 响应缓存、响应聚合
- API 文档（Swagger/OpenAPI）
- 证书管理（SSL）

**高可用部署**：网关外层通过 Nginx 负载转发，避免单点风险。

### Spring Cloud Gateway

基于 Spring WebFlux（Reactor + Netty）实现的响应式网关。

**工作流程**：
1. 路由判断：Gateway Handler Mapping 通过 Predicate 断言匹配路由
2. 请求过滤：Gateway Web Handler 过滤器链修改请求（Pre-Filters）
3. 服务处理：后端服务处理请求
4. 响应过滤：Post-Filters 处理响应
5. 响应返回：最终返回客户端

**断言**：对表达式进行真假判断，多个断言需同时满足才匹配路由。请求匹配多个路由时，匹配第一个。

**限流**：内置 RedisRateLimiter（基于 Redis + Lua），可结合 Sentinel 实现更强大的流量控制。

**全局异常处理**：实现 ErrorWebExceptionHandler 并重写 handle 方法。

### 分布式 ID

分库后数据库自增主键无法满足唯一性，需要分布式 ID。

**要求**：
- 全局唯一
- 高性能、高可用
- 方便易用
- 安全（无敏感信息）
- 有序递增（提升数据库写入速度）
- 有具体业务含义
- 独立部署

### 常见解决方案

**数据库方案**：
- 主键自增：简单但并发量小、存在单点问题
- 号段模式：批量获取 ID 存入内存，减少数据库访问

**NoSQL 方案**：
- Redis incr：性能好、有序递增，但有类似数据库的问题

**算法方案**：
- UUID：全局唯一但无序、占用空间大、不适合数据库主键
- Snowflake（雪花算法）：有序递增、灵活，但依赖时间（时钟回拨问题）、依赖机器 ID

**开源框架**：
- UidGenerator（百度）：改进雪花算法，28 位时间戳 + 22 位机器 ID + 13 位序列号
- Leaf（美团）：号段模式 + 雪花算法，支持双号段，解决时钟回拨问题，弱依赖 Zookeeper
