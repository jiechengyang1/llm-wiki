# ShardingSphere 分库分表

## 基础

分库分表是应对数据量和访问量增长带来的单机数据库性能瓶颈的解决方案。ShardingSphere 是 Apache 顶级项目，提供数据分片、分布式事务、读写分离等能力。

## 核心

### 分库分表类型

**垂直拆分**：按业务属性将表的不同列拆分到不同库或表，减少单表宽度。垂直分库按模块分库，垂直分表按列访问频率拆分。

**水平拆分**：按行将数据拆分到多个库或表，解决单表数据量过大的问题。水平分库将数据分到不同服务器，水平分表将数据分到同一库的多张表。

**总结**：水平按行切分，垂直按列切分。

### 为什么要分库

- 减小单库压力：单库连接数有限，数据量和访问量增长后单机性能下降
- 减少锁竞争：高并发下单个数据库锁竞争影响性能
- 水平扩展：通过增加节点进行水平扩展
- 隔离故障：单库故障不影响其他库，提高可用性

### 为什么要分表

- 减少单表数据量：数据量过大查询性能下降
- 优化索引使用：减少索引大小，提高查询效率
- 分散写入压力：大表插入更新性能受影响
- 减少锁竞争：减少并发写操作的锁竞争

### 分片策略

**Hash 分表**：按 ID 对表数目取模映射。优点是映射速度快，缺点是扩表需要重新 hash。

**Range 分表**：按范围分表（如按时间）。优点是简单，缺点是容易产生热点偏向问题。

### 分库分表迁移

**双写方案**：

第一阶段（在线双写，查询走老库）：数据同时写入新旧库，定时任务对比差异并补齐。

第二阶段（在线双写，查询走新库）：完成数据同步校验后，切换读流量到新库。

第三阶段：旧库下线。

**扩容挑战**：全量迁移和 binlog 增量同步并行时可能发生主键冲突、数据不一致等问题。

### MySQL 连接数

MySQL 5.5-5.7 默认最大连接数 151，上限可达 100000。
