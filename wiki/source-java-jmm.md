# 资料摘要：Java内存模型之JMM

## 基本概念

JMM（Java Memory Model）是Java虚拟机规范定义的抽象模型，用于屏蔽不同硬件和操作系统的内存访问差异，解决多线程可见性和有序性问题。

## 三大特性

### 1. 可见性
一个线程对共享变量的修改，能被其他线程立即看到。

### 2. 有序性
程序执行顺序按照代码先后顺序（单线程内）。

### 3. 原子性
不可分割的操作，要么全部执行要么全部不执行。

##  Happens-Before规则

定义操作间的偏序关系，是JMM最核心的概念：

1. 程序顺序规则
2. 监视器锁规则
3. volatile变量规则
4. 线程启动规则
5. 线程终止规则
6. 线程中断规则
7. 传递性

##  volatile语义

- **可见性**：每次读取强制从主内存读，写直接刷回主内存
- **有序性**：禁止指令重排序（内存屏障）
- **不能保证原子性**（如i++）

##  volatile应用场景

- 状态标志位
- 单例模式双重检查锁定
- 读多写少的数据

## CPU缓存结构

```
寄存器 → L1/L2 Cache → L3 Cache → 主内存
```

缓存行（Cache Line）大小通常为64字节。

## 缓存一致性协议

MESI（Modified-Exclusive-Shared-Invalid）是常见的缓存一致性协议。

## 内存屏障

| 屏障类型 | 作用 |
|----------|------|
| LoadLoad | 防止load1重排到load2之后 |
| StoreStore | 防止store1重排到store2之后 |
| LoadStore | 防止load1重排到store2之后 |
| StoreLoad | 防止store1重排到load2之后 |

## 指令重排序

- 编译器优化重排序
- 指令级并行重排序
- 内存系统重排序

## 常见问题

**为何需要内存屏障？**
CPU和编译器可能为性能优化而进行指令重排序，需要内存屏障保证可见性和有序性。
